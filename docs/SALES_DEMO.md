# 大東市交通政策課向け 5〜10分デモ台本

## この資料の立場

大東市の公開情報だけで作った技術検証です。市の公式データではなく、特定アプリへの反映を約束するものでもありません。

## 0:00〜1:00 — 1. 現在公開されているGTFS-JP

お伝えすること:

> 大東市は、コミュニティバス等の停留所・時刻・運行日をGTFS-JPで公開されています。令和8年度版には、2026年4月改定後の成人区間運賃もFares v1で1,990ルール入っています。今回の出発点は、この既存資産です。

見せるもの:

- 公式公開ページ
- `docs/CURRENT_GTFS.md` のfile件数
- 成人120/240/270/300/330/350/390円がすでにあること

強調点: 「今のGTFSが悪い」ではなく、「今ある良いデータを拡張する」。

## 1:00〜2:00 — 2. 今回公開情報だけで作った試作品

> 公式GTFSを直接編集せず、取得、解析、Fares v2生成、統合、ZIP化、検証を自動化しました。小児、高齢者、障害者等、支払媒体、限定乗継を追加しています。判断できないことは推測せず未確定事項に残しています。

見せるもの:

- `README.md` 冒頭
- `dist/daito_gtfs_fares_v2.zip`
- 自動テスト8件、Validator error 0

## 2:00〜3:00 — 3. Fares v2とは

> 従来は主に「この区間はいくら」でした。Fares v2では、「誰が」「何で払い」「どの商品が」「どの区間に適用され」「乗継時にどうなるか」を別々の表で結びます。

短い対応:

- 人: rider_categories
- 支払方法: fare_media
- 金額: fare_products
- 区間: fare_leg_rules
- 乗継: fare_transfer_rules

## 3:00〜5:00 — 4. 大東市の運賃制度をどう表現したか

> 240円と270円の境界は、今のGTFSにある区間表をそのまま使いました。120円特定区間は割引なしとして全区分120円です。270円の半額は公式端数処理により140円です。南部と東部は同じ300円でも、制度と距離帯が違うので別商品です。

> 65歳以上はコミュニティバスで現金のみ。障害者割引はサービスごとに公式記載範囲が違うため、同じ対象と推測していません。市役所乗継は公式案内された接続だけに限定しました。

含めなかったもの:

- 幼児の同伴人数条件
- 介護者同行の自動判定
- 根拠のない乗継時間
- 定期券の不完全な商品化

## 5:00〜6:30 — 5. Before / After

デモを開き4例のうち2〜3例を見せる。

### 例A: 住道駅前［北］ → 三箇西

- Before: 成人270円
- After: 65歳以上 + 現金 = 140円
- 注意: 声掛けという運用は別に残る

### 例B: 住道駅前［北］ → 市役所

- 小児でも特定区間は120円
- 「半額」と機械が誤解しない

### 例C: 南新田南 → 住道駅南 → 市役所

- 通常合計360円
- 紙の乗継券による大人120円引き
- 最終240円

言い方:

> ここで見せているのは、GTFS仕様上たどれる結果です。この画面がGoogle Mapsにそのまま出る、という説明ではありません。

## 6:30〜7:30 — 6. 市側にどんな可能性があるか

- 運賃改定時に「どの人・媒体・区間が変わるか」を差分確認しやすい。
- 同じ運賃台帳を複数の案内・検証先へ渡せる。
- 成人以外の運賃を検索サービスへ伝える土台になる。
- 乗継制度を人向け文章だけでなく、計算可能な関係として保管できる。
- Validatorとテストにより、公開前の参照切れや形式崩れを検出できる。

「可能性」と「確認済み効果」を分けて話す。

## 7:30〜8:30 — 7. 制約

- consumerのFares v2対応には差がある。
- 資格確認、同伴人数、紙券発行はデータだけで自動化できない。
- 今回は定期券を含めていない。
- 市・事業者の業務確認前なので公式化できない。
- GTFS Validator error 0でも制度解釈の正しさまでは保証しない。

## 8:30〜10:00 — 8. 次に実証するなら

1. 市・運行事業者と、20程度の代表O-D・利用者区分・媒体・乗継を突合。
2. 乗継券の時間条件とIC併用条件を確認。
3. 検証用経路検索エンジンまたは対応consumerで入力と表示を比較。
4. 運賃改定の更新・承認フローを小規模に試す。
5. 定期券は別テーマとして、商品台帳とconsumer対応を確認してから設計。

締めの一言:

> この試作品の価値は、運賃を増やして見せることだけではありません。公開情報、設計判断、生成方法、検証、限界を一つの更新可能な工程にした点にあります。次の実証では、実際の運用ルールとconsumerの挙動を市と一緒に確認できます。
